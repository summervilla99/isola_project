# ISOLA 모바일 게임 개발 방향

> 결정일: 2026-10-28  
> 상태: 구현 기준으로 확정. 기존 웹 MVP 문서와 충돌하는 항목은 이 문서가 우선한다.

캐릭터·섬·UI의 시각 품질과 리뷰 기준은 [`ART_DIRECTION.ko.md`](./ART_DIRECTION.ko.md)를 따른다. 기능 완료보다 해당 품질 게이트 통과를 우선한다.

## 1. 한 문장 정의

**ISOLA는 친구 4~8명이 한 섬에 살며, 사람·동물·정령을 자유롭게 섞은 작은 존재가 되어 자신의 취향을 살아 있는 공간으로 가꾸는 모바일 소셜 코지 게임이다.**

목록형 아카이브에 3D 배경을 붙이는 서비스가 아니다. 사용자는 앱을 켜자마자 게임 세계 안에 있고, 설정·아카이브·친구 기능도 캐릭터와 공간의 상호작용으로 만난다.

## 2. 확정된 제품 결정

| 항목 | 결정 |
|---|---|
| 우선 플랫폼 | iOS·Android 네이티브 앱. 태블릿 대응 후 PC/Mac 검토 |
| 게임 엔진 | Godot 4.7 안정판, GDScript, GL Compatibility에서 시작해 실기기별 Mobile renderer 검증 |
| 화면 | 16:9 가로형 모바일 우선. 게임 장면이 항상 전체 화면을 차지하고 HUD는 최소화 |
| 그래픽 | 키치하고 감각적인 로우폴리 3D, 젤리·클레이 장난감 질감, 선명한 캔디 팔레트 |
| 캐릭터 비율 | 2.5~3등신, 두 발로 걷는 공통 골격 |
| 존재 표현 | 인간·카피바라·동물·정령 파츠를 성별 잠금 없이 조합 |
| 세계 구조 | 하나의 초대 전용 공동 섬 + 개인 집·정원 + 공동 광장 |
| MVP 접속 | 비동기 방문·메시지 우선, 이후 4~8명 실시간 동기화 |
| 서버 | 기존 Supabase Auth·Postgres·RLS·Realtime 재사용 |
| 웹의 역할 | 기존 알파 보존. 장기적으로 소개·초대 링크·운영 도구 역할 |

## 3. 경험의 중심

### 3.1 핵심 판타지

“현실에서 설명하기 어려운 나도 이 섬에서는 귀여운 하나의 존재로 자연스럽게 살아간다.”

캐릭터 제작 화면은 성별을 먼저 묻지 않는다. 사용자는 기본형을 고른 뒤 귀, 얼굴, 피부·털, 뿔, 꼬리, 헤어, 옷, 빛 효과를 섞는다. `사람`, `카피바라`, `정령`은 배타적인 종족이 아니라 시작 프리셋이다.

### 3.2 고유 게임 루프

1. 오늘 마음에 남은 책·영화·문장·음료·기억을 **보물**로 기록한다.
2. 보물은 책, 종이 나비, 프로젝터, 메시지 병, 빛나는 병, 식물 같은 공간 오브젝트가 된다.
3. 집이나 정원에 놓으면 주변의 빛·꽃·소리·날씨가 조금씩 달라진다.
4. 친구가 방문해 오브젝트를 만지고 감상, 스티커 반응, 짧은 메시지를 남긴다.
5. 친구의 반응은 꽃이 피거나 작은 정령이 태어나는 식으로 공간에 흔적을 남긴다.

재화 수확과 접속 보상보다 자기표현과 친밀한 발견을 보상한다. 꾸미기 아이템 수량 경쟁을 핵심으로 삼지 않는다.

## 4. 첫 사용자 경험

### 4.1 첫 5분

1. 로고와 섬을 전체 화면으로 본다.
2. “너는 어떤 존재로 이 섬에 올래?”에 답하며 캐릭터를 만든다.
3. 작은 배가 도착하거나 별빛이 내려오는 10초 내외 연출을 본다.
4. 공동 광장에서 친구 또는 안내 정령을 만난다.
5. 빈 집에 들어가 첫 가구를 놓는다.
6. 첫 보물을 기록해 전시한다.

가입은 세계관을 끊는 폼이 아니라 도착 절차에 녹인다. 이메일 인증이 필요한 순간에도 섬 배경과 캐릭터를 유지한다.

### 4.2 돌아오는 2분

- 집 앞에 피어난 꽃이나 우편함의 반짝임으로 새 반응을 발견한다.
- 친구 집을 한 곳 방문한다.
- 보물 하나를 남기거나 기존 공간을 조금 바꾼다.
- 할 일이 없으면 섬을 걷고 파도·노을·친구의 흔적을 감상하고 종료해도 된다.

## 5. 캐릭터 시스템

### 5.1 공통 골격

- 모든 기본형은 두 팔·두 다리의 동일 휴머노이드 골격과 상호작용 앵커를 공유한다.
- 기본 애니메이션: idle, walk, run, sit, wave, hug, hold-item, sleep.
- 가구는 손, 엉덩이, 발, 머리 앵커에 맞춰 한 번만 제작한다.
- 네 발 변신은 MVP 이후 별도 리그를 사용하는 특별 능력으로 검토한다.

### 5.2 파츠 분류

- 머리형: 사람, 카피바라, 고양이, 토끼, 새, 물방울 정령.
- 얼굴: 눈, 눈썹, 코·주둥이, 입, 볼터치, 주근깨.
- 신체: 키 프리셋, 통통함 프리셋, 피부·털·발광 재질.
- 부착물: 귀, 뿔, 꼬리, 날개, 새싹, 버섯, 꽃.
- 스타일: 헤어, 상의, 하의, 원피스, 신발, 가방, 모자.

정체성·대명사 입력은 선택적 프로필이다. 외형 파츠, 목소리, 옷을 잠그는 조건으로 사용하지 않는다.

## 6. 공간과 조작

### 6.1 탐험 모드

- 왼쪽 아래 가상 조이스틱으로 이동한다.
- 상호작용 가능한 대상 근처에서는 캐릭터가 부드럽게 위치와 방향을 보정한다.
- 오른쪽 아래 상황 버튼 하나가 `열기`, `읽기`, `앉기`, `안아주기`로 바뀐다.
- 카메라는 쿼터뷰를 유지하고 한 손 드래그로 제한 회전, 두 손가락으로 제한 줌한다.
- HUD는 프로필, 가방, 카메라, 우편함만 남기고 탭 바·대시보드는 두지 않는다.

### 6.2 꾸미기 모드

- 캐릭터가 작은 망치를 들면 편집 모드로 전환된다.
- 하단 카탈로그에서 소품을 끌어 공간에 놓는다.
- 한 손 드래그 이동, 탭 회전, 두 손가락 확대/축소를 사용한다.
- 격자 스냅과 자유 배치를 모두 제공하되 MVP는 격자 스냅을 기본값으로 한다.
- 저장 전 전체 동선을 검사해 문과 필수 오브젝트가 막히지 않게 한다.

## 7. 기술 구조

```text
Godot mobile client
├─ Presentation: scene, avatar, animation, mobile HUD
├─ Game domain: movement, interaction, decoration, archive-object mapping
├─ Local state: settings, draft layout, asset cache
└─ Network gateway
   ├─ Supabase Auth (PKCE/deep link)
   ├─ PostgREST/RPC (existing RLS)
   ├─ Storage (approved image assets only)
   └─ Realtime (presence/broadcast; Phase 2)
```

- 앱에는 Supabase publishable key만 포함한다. secret/service-role key를 포함하지 않는다.
- 인증 세션은 OS의 보안 저장소 플러그인 도입 전까지 평문 프로젝트 파일에 저장하지 않는다.
- 네트워크 계층은 Godot `HTTPRequest` 기반 인터페이스로 격리해 mock 테스트가 가능하게 한다.
- 서버 권한은 기존 RLS와 SECURITY DEFINER RPC를 기준으로 유지한다. 클라이언트 상태를 권한 근거로 신뢰하지 않는다.
- 캐릭터 설정은 파츠 ID와 팔레트 ID만 저장하고 GLB 바이너리를 사용자별로 생성하지 않는다.

## 8. 3D 에셋 원칙

- Blender → glTF 2.0/GLB → Godot import 경로를 표준으로 한다.
- 캐릭터 한 개 화면 기준 30k triangles 이하, 재질 4개 이하, 텍스처 atlas 우선.
- 가구는 LOD0 5k triangles 이하를 기본 예산으로 한다.
- 투명 재질을 제한하고 모바일에서는 구워진 조명과 단순 그림자를 우선한다.
- 색상 변형은 별도 메시 복제 대신 팔레트 재질로 처리한다.
- 초기 수직 구현은 엔진 기본 도형으로 검증하고, 캐릭터 실루엣 확정 후 제작 에셋으로 교체한다.

## 9. 단계별 개발

### M0 · 감각 검증 수직 구현 — 진행 중

- 가로형 전체 화면 섬, 키치 팔레트, 카피바라·사람·정령 프리셋.
- 캐릭터 생성 → 섬 도착 → 이동의 연속 흐름.
- iOS 시뮬레이터 빌드와 조작·프레임 검증.
- 산출물 승인 기준: 첫 화면이 대시보드가 아니라 게임으로 느껴지고 캐릭터를 바꿔보는 재미가 있다.

### M1 · 오프라인 플레이그라운드

- 조이스틱 이동, 카메라, 충돌, 상호작용.
- 집 입장, 가구 12종 배치, 저장·불러오기.
- 공통 골격 캐릭터 3종과 핵심 애니메이션.

### M2 · 계정과 취향 보물

- 모바일 딥링크 인증, 세션 복원, 캐릭터 저장.
- 책·영화·문장·위스키 기록을 보물 오브젝트로 전환.
- 개인 집·정원과 공개 범위 연결.

### M3 · 친구 섬

- 초대 링크, 4~8명 공동 섬, 개인 집터.
- 비동기 방문, 스티커 반응, 메시지, 푸시 알림.
- 차단·신고·공개 범위·데이터 삭제 검증.

### M4 · 실시간 함께 있기

- Supabase Realtime presence/broadcast로 위치·애니메이션 상태 동기화.
- wave, hug, hand-hold 등 제한된 비언어 상호작용.
- 연결 끊김, 백그라운드 전환, 저속 네트워크 보정.

### M5 · 비공개 베타

- TestFlight와 Google Play 내부 테스트.
- 4~8인 친구 그룹 5팀 이상으로 잔존·꾸미기·초대 흐름 관찰.
- 성능, 발열, 크래시, 접근성, 안전 정책 통과 후 공개 범위 결정.

## 10. 지금 만들지 않는 것

- 공개 피드, 팔로워 수, 랭킹, 무작위 매칭.
- 유저 거래, 가챠, 희소성 투기, 암호화폐.
- 채팅방이 중심인 메타버스 화면.
- 생성형 AI가 매번 3D 모델을 만드는 기능.
- 수십 종 미니게임, 농사·낚시·제작 경제.
- 완전한 네 발 캐릭터와 해당 가구 애니메이션.

초기 목표는 기능 수가 아니라 **존재 만들기, 걷기, 꾸미기, 친구의 취향을 발견하기** 네 가지 감각의 완성도다.
