# ISOLA 구현 결정

## ADR-001: GitHub 프로젝트와 Next.js 유지

사용자 지정 저장소에 직접 개발한다. Sites 호스팅 등록은 하지 않는다. React 19와 R3F 9를 사용하고 lockfile로 실제 설치 버전을 고정한다. `AGENTS.md`는 설치된 Next.js가 생성하는 개발 지침이다.

## ADR-002: 첫 알파의 API는 Supabase RPC

기획서의 `/api/v1` REST 인터페이스 대신 `isola_state`, `isola_mutate`, `isola_invite` RPC를 첫 구현에 사용한다. 한 번의 변경을 PostgreSQL 트랜잭션으로 처리하여 API와 DB 권한이 분산되는 문제를 줄인다. 인증은 사용자 JWT이며 서비스 키가 없다.

직접 테이블 쓰기는 authenticated에도 허용하지 않는다. 읽기는 RLS가 적용된다. 초안이 포함된 spaces 테이블의 직접 읽기는 소유자 전용이며 친구 방문에는 공개본만 투영하는 RPC를 사용한다. SECURITY DEFINER 함수는 고정된 빈 search_path와 완전 수식 테이블명, auth.uid 기반 검증을 사용한다.

초기 `isola_state`는 현재 섬 데이터의 허용된 부분을 한 번에 받는다. 계정당 기록 500개 제한을 두었지만 페이지네이션은 아직 없다. 섬당 기록·댓글이 증가하기 전에 목록별 커서 API로 분리해야 한다. 실제 미니게임·실시간 기능에 이 snapshot API를 사용하지 않는다.

## ADR-003: 샘플 모드는 별도 데이터 저장소

샘플은 명시적 버튼으로만 진입한다. 브라우저에만 저장되며 샘플 친구는 온라인 사용자가 아니다. 실계정 데이터가 localStorage 샘플 공간에 복제되지 않는다. Supabase 인증 세션 저장은 SDK가 관리한다. 서비스 워커는 개인 정보, 인증 세션, API 응답을 저장하지 않는다.

## ADR-004: 생성형 에셋보다 도형 수직 구현 우선

자체 제작 Three.js 도형으로 집·자연·아바타·가구를 구성한다. 에셋 파일 다운로드, 외부 라이선스, 리깅 실패 없이 상호작용을 먼저 검증한다. 정식 GLB 카탈로그는 후속 교체 대상이다. 초기 8개 소품은 기획서의 24개 목표보다 적다.

## ADR-005: 프라이버시와 삭제

개인 기록/공간은 private 기본값. 공개본 발행은 명시적 공개 동작이다. 방장에게 개인 데이터 열람 특권을 주지 않는다. 차단은 양방향 조회 제한이다. 신고 원문은 운영자 전용이며 신고자는 자기 접수만 확인할 수 있다. 계정 삭제 요청 후 일반 앱 접근이 즉시 막히지만 Auth 계정의 실제 삭제는 운영자가 수행해야 한다.

## ADR-006: 의존성 최소화

첫 구현은 React 상태와 Supabase SDK로 구성했다. Zustand/TanStack Query는 필요성이 확인되면 도입한다. 에디터·세션 분리가 커지기 전 단일 앱 컴포넌트를 기능별로 나누는 리팩터링이 필요하다.

## ADR-007: 기본 로그인 링크와 OTP 동시 지원

실제 Supabase 대시보드의 기본 메일은 로그인 링크이고, 템플릿 수정에는 커스텀 SMTP가 필요했다. 별도 메일 업체 계약 없이 개발을 진행하도록 기본 링크를 수용하고 OTP 입력도 유지한다. 로그인 링크는 현재 앱 origin으로 돌아온다. 초대 수락은 로그인과 분리한 명시적 작업이다.
